## 페르소나와 에셋

바리스타를 특수 직원 페르소나로 등록한다. 직원용 프로필·대화·작업 정책 데이터는 손님 테이블과 별도 관리한다. 말투와 성격의 세부 내용은 구현 시 초안으로 구분하며 모델 파일명만으로 추정하지 않는다.

제안 테이블:

| 구분 | 주요 필드와 역할 |
| --- | --- |
| 직원 프로필 | 직원 ID, 표시 이름, 역할, 성격, 말투, 관심사, 응답 원칙, 에셋 참조 |
| 상호작용 | 상황 ID, 시작 조건, 대화 의도, 예시·어휘, 후속 질문과 응답, 반복 제한 |
| 작업 정의 | 작업 종류, 수행 가능 주체, 선행 조건, 실제 수행 절차, 완료·실패 조건 |
| 작업 위치 | 작업대/설비 참조, 접근 지점, 서는 위치, 작업 방향, 점유 범위 |
| 분담·재촉 정책 | 우선순위, 지연 판정, 재촉 간격, 재배정·취소 조건 |

대화는 인사·업무 확인·분담 제안·진행 문의·도움 요청·되묻기·지연 재촉·완료 반응·실수 대응·업무 사이 잡담을 지원하도록 설계한다. 손님보다 넓은 주제와 후속 대화를 제공하고, 기존 API → 로컬 모델 → 자동 답변 흐름의 재사용 가능한 부분을 활용한다. 예시 문장만 반복하는 구조로 축소하지 않는다. 모델 응답이 실제 작업 상태를 바꾸거나 완료 사실을 만들어 내게 하지 않는다.

## 주문과 작업 분담

1. 주문 접수 시 주문 ID에 연결된 작업과 선행 조건을 만든다. 숨겨진 정답 메뉴를 동료가 먼저 알아맞히는 방식으로 기존 주문 추론을 생략하지 않는다. 메뉴 확인이 필요한 작업은 그 정보가 확정될 때까지 대기한다.
2. 스케줄러가 수행 가능 여부, 현재 담당 작업, 설비 점유, 주문 우선순위에 따라 플레이어와 바리스타의 작업을 나눈다. 구체적인 분담 규칙은 실제 제조 구조를 확인한 뒤 정한다.
3. 화면에서 각자의 담당 작업과 진행·막힘을 알아볼 수 있게 한다. 같은 음료·재료·작업대의 중복 실행을 막는다.
4. 바리스타는 자신의 작업 위치로 이동해 방향을 맞추고 실제 작업을 실행한다. 완료는 제조·서빙 시스템의 실제 결과로 판정한다.
5. 실행 가능한 플레이어 담당 작업이 일정 시간 지연되면 바리스타가 구체적인 작업을 짚어 재촉한다. 선행 작업 미완료, 경로 막힘, 설비 사용 중을 플레이어의 지연으로 오인하지 않는다.
6. 재촉은 쿨다운과 표현 중복 방지를 둔다. 진행·완료되면 예정된 재촉을 취소하고, 손님 대화나 입력 중에는 겹쳐 읽기 어렵지 않게 표시 순서를 조절한다.
7. 주문 취소·손님 이탈·영업 전환·초기화 시 관련 작업과 점유를 해제한다. 이전 작업의 늦은 완료나 응답이 새 주문에 반영되지 않게 한다.

작업 상태는 대기 → 배정 → 이동 → 작업 → 완료를 기본으로 하고, 막힘·실패·취소를 구분한다. 재배정 시 기존 목적지와 작업 예약을 먼저 정리한다.

## 작업 위치와 이동

바리스타 위치는 **할당된 작업**으로 결정한다. 여기서 follow path는 작업 위치까지의 경로 추종이며 플레이어를 따라다니는 기능이 아니다. 작업이 없으면 통행과 작업을 방해하지 않는 대기 위치를 사용한다.

- 작업별 접근 지점·서는 위치·방향·사용 공간을 지정한다. 할당 → 작업 위치 예약 → 경로 계획 → 이동 → 도착과 방향 정렬 → 실행을 연결한다.
- 플레이어와 바리스타에 충돌 범위와 최소 간격을 두고, 스폰·이동·작업 도착 시 겹치지 않게 한다. 플레이어를 밀어내거나 순간이동해 통과하는 방식은 사용하지 않는다.
- 먼저 통행 가능한 경로를 구한 다음 경유점의 연결을 베지어 곡선으로 다듬는다. 캐릭터 폭과 여유 공간을 포함한 곡선 구간 검사를 거쳐 가구·벽·작업대를 가로지르지 않게 한다. 곡선이 불가능한 좁은 구간은 감속해 통과하고 안전한 연결을 우선한다.
- 플레이어가 경로·목적지를 가로막으면 안전 간격에서 감속·정지하고, 우회 가능한 경우 재탐색한다. 작업 위치를 확보하지 못하면 대기 상태와 사유를 표시한다.
- 곡선의 진행 거리에 맞춰 속도를 제어하고 접선 방향으로 몸을 부드럽게 돌린다. 출발·정지와 Idle/Walk 전환을 연결하고 실제 이동 속도에 맞춰 발 미끄러짐을 조정한다.
- 작업 변경·취소 시 이전 경로를 폐기하고 새 작업 위치를 기준으로 재계획한다. 짧은 프레임마다 경로가 흔들리지 않게 한다.

## 대화 진입과 기록 UI

- 플레이어가 바리스타 바로 앞의 가까운 범위에 있고 카메라 전방이 바리스타를 향하며 시야가 가려지지 않았을 때 바리스타 대화 토글을 활성화한다. 진입·해제 범위에 여유를 둬 경계에서 깜박이지 않게 한다.
- 조건을 충족하면 대화 토글이 있다는 안내를 잠깐 띄운다. 안내 시간이 끝나더라도 조건이 유지되는 동안 토글은 사용할 수 있게 하고, 안내가 매 프레임 또는 짧은 시선 변화마다 반복되지 않게 한다.
- 기존 E 손님 대화 및 F 제조·서빙과 입력 우선순위를 맞춘다. 동료를 명확히 바라보며 접근한 경우 대상을 표시하고, 대화 시작 후에는 카메라·커서 상태가 바뀌어도 대상이 손님으로 전환되지 않게 한다.
- ‘진행 중 대화’는 손님만 표시한다. 바리스타에게서 온 재촉이나 활성 대화를 이 손님 목록에 넣지 않는다.
- 이전 손님별 대화 로그를 고르는 창의 **최상단에 바리스타 기록 항목을 고정**한다. 기록이 없어도 항목과 빈 상태를 제공하며, 아래의 기존 손님별 기록은 유지한다.
- 최상단 항목은 기록 열람용이다. 실제 바리스타 대화 시작은 공간·시선 조건을 거쳐야 한다. 접근 조건으로 열어 대화 중인 화면과 기록 열람 상태를 구분한다.
- 고객 주문·서빙 대상과 현재 대화 상대를 분리한다. 바리스타와 대화하거나 기록을 읽어도 주문 선택, 큐, 서빙 대상이 바뀌지 않게 한다.
- 바리스타 대화 이력과 생성 요청을 손님과 분리하고, 대상 전환·취소 뒤 응답이 다른 인물 기록에 섞이지 않게 한다. 기본 기록은 기존과 같은 실행 중 메모리 범위로 두며 별도 저장 기능은 추가하지 않는다.

## 적용 순서와 의존성

1. 선행 세션 완료와 변경 사항 확인, 최신 제조·카탈로그·HUD 흐름 재확인.
2. 직원용 에셋·프로필·전용 기록 구조와 카페 내부 배치 준비. GUID와 기존 손님 등록을 보존.
3. 주문 하나에서 분담 → 작업 위치 이동 → 실제 완료 → 지연 시 재촉까지 연결.
4. 충돌 회피·베지어 경로·속도와 회전·Idle/Walk 조정.
5. 접근·시선 기반 토글, 잠깐 안내, 직원 대화 생성과 최상단 기록 연결.
6. 대화 종류와 후속 상호작용 확대, 주문 취소·막힘·초기화 회귀 확인.

직원 제어·스케줄러·직원 대화는 역할을 나눠 추가한다. `CafeSession`, `CafeHud.Conversations`, `CafeHud.Merged`, `CafeHud.Status`, 손님 카탈로그/임포트, `CafeBrewStation`, `CafeServeCounter`와 연결 지점을 다시 추적한다. 기존 `BaristaView`는 이름만으로 동료 NPC 컨트롤러라고 간주하지 않는다. 연결된 Editor가 있으면 해당 도구를 우선하며, 열린 씬 YAML 직접 편집이나 씬 전체 재생성을 기본 수단으로 쓰지 않는다.

## 완료 조건과 검증

코드·데이터·참조 검사에서는 직원이 손님 큐에 섞이지 않는지, 작업이 중복 실행되지 않는지, 완료·취소 뒤 예약과 늦은 응답이 정리되는지, 대화 기록과 서빙 대상이 분리되는지 확인한다.

실제 Play 확인은 사용자가 담당한다. 다음 연속 흐름에서 화면과 조작을 확인할 수 있게 인계한다.

- 주문 → 역할 분담 → 각자 제조 → 서빙 → 다음 주문이 연결되고, 지연 시 실제 미완료 작업에 맞게 재촉한다.
- 작업 변경에 따라 바리스타가 올바른 위치로 이동한다. 플레이어가 앞을 막거나 작업대를 점유해도 겹침·관통 없이 대기·우회하고 다시 작업한다.
- 회전·속도·보행이 연결되어 직각 꺾임, 미끄러짐, 정지 떨림이 두드러지지 않는다.
- 가까이서 바라볼 때 토글이 활성화되고 안내는 잠깐 나타난다. 멀리 있거나 가려졌을 때는 활성화되지 않는다.
- 바리스타 대화·재촉·손님 주문이 겹쳐도 말한 대상과 현재 작업이 명확하며, 긴 대화·한글 입력·취소·재진입이 자연스럽다.
- 진행 중 목록은 손님 전용이고, 바리스타 기록은 이전 대화 목록 최상단에서 별도로 열람된다.

초기 계획 수립 때는 압축 항목과 관련 소스의 읽기 전용 확인만 수행했다. 이후 구현·검증 상태는 이 문서 상단의 최근 추가 요구와 검증 순서를 기준으로 한다. 실제 거리·시야각·안내 시간 등은 Play 결과에 맞춰 조정한다. 새 빌드는 생성하지 않았다.
