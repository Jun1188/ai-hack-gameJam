# 카페 손님·대기 큐 프로토타입

현재 기준은 제공된 `카페_손님_데이터테이블.xlsx`, `카페_메뉴_데이터테이블.xlsx`와 사용자의 최신 지시다. 원본은 수정하지 않았다. Unity `6000.6.8f1`, `Assets/Scenes/test-serv.unity`를 사용한다.

## 플레이

WASD 이동, 마우스 시점, Tab 시점/커서 전환, E/Esc 커서 해제. 가운데 큐에서 손님을 선택하고 오른쪽 HOT/ICE 버튼으로 제공한다. 자동 서빙은 없다. 손님별 대화는 왼쪽 위에 표시한다. 접수 전·서빙 대기·후기 탭으로 다른 손님을 볼 수 있다.

- 새 손님은 기본 60초 간격으로 도착한다. 접수 전 `inactive-waiting`은 최대 4명이며 가득 차면 새 입장을 받지 않는다. 기존 대기자의 만족도는 기다린 시간에 비례해 감소한다.
- 기본 60초 간격으로 가장 먼저 들어온 손님부터 주문을 접수하고 `active-waiting`으로 옮긴다. 서빙 대기에는 인원 상한을 두지 않는다. 화면의 임시 캐릭터만 최대 12개로 제한하며, 논리 큐와 선택 목록은 잘리지 않는다.
- 입력과 무관하게 기본 30초마다 대기 시간 구간에 맞는 잡담을 검색한다. 현재 큐·이전 출력·누적 시간·방문 횟수를 사용하며 (대기 구간 0~60 / 60~120 / 120초 이상), 같은 문장을 다시 고르지 않는다. 주문과 수령 결과를 지어내지 않는다.
- 주문 후 180초 안에 받지 못하면 0점 후기 후 서빙 대기에서 빠진다. 엑셀의 ‘인내심 -20%’ 사정은 해당 손님의 기한을 144초로 줄인다. 기한 도달은 서빙보다 먼저 검사하므로 이탈 후 서빙이나 중복 서빙이 불가능하다.
- 받은 손님은 즉시 반응하고 기본 3.5초 뒤 별점·후기를 표시한다. 큐는 이 시간에도 계속 움직인다.
- 메뉴 밖 요구는 **5%**다. 확률은 매 방문 추첨이며 20명마다 반드시 1명이라는 뜻은 아니다. 기본 요청은 카페모카·복숭아 에이드·진한 코코아·흰 우유이며 기존 주문 취향과 가까운 후보에서 뽑는다.

`CafeSession.queueSettings`에서 인원·시간·감점·확률을 조정한다. 잘못된 값/NaN/무한대는 거부한다. 입장 차단 횟수는 `RejectedArrivals`, 완료 후기는 최근 64개를 보관한다. 이는 활성 대기 큐 상한이 아니다.

## 만족도

미수령 시간 초과만 0점이다. 수령 시에는 아래 계산을 1~5점으로 제한한다.

`round(1 + 4 × 메뉴 유사도 - 접수 전 대기초 × 0.005 - 접수 후 대기초 × 0.008)`

정확한 메뉴·온도는 유사도 1, 같은 메뉴의 다른 온도는 0.8이다. 다른 메뉴는 단맛·쓴맛·우유·과일·탄산·커피 유무의 가중 거리와 온도로 계산하며 최대 0.95, 최종 별점 최대 4점으로 제한한다. 쓴맛·과일의 수치화는 원본의 정량값이 아닌 **명시적 파생 휴리스틱**이다. 실제 원본 메뉴 속성도 별도 보존했다. 여섯 번째 특성은 커피 유무이며 ‘카페인 없음’의 의학적 보증이 아니다.

접수 전·후 대기 감점은 각각 기록하며, 지연 후기에는 실제 초가 들어간다. 정확한 음료를 받아도 오래 기다리면 높은 점수가 보장되지 않는다. 활성 매개변수는 `visited_inactive`, `visited_active`, `repeat`, `inactive`, `active`, `received`, `accurate/similar/different`, `off_menu`, `delayed`, `timeout`이다. 인구통계나 장애 여부는 감점에 쓰지 않는다.

## 데이터와 로컬 검색 구조

엑셀에서 메뉴 11종, 손님 유형 16개, 상황 33개, 메뉴 가중치 176개, 다국어 금지 표현 57개를 가져왔다. 수치 나이나 개인 이름은 원본에 없으므로 만들어 넣지 않고 유형·연령 표현을 사용한다. 외형 파츠도 필드에 보존하지만 실제 모델/애니메이션은 아직 임시 도형이다.

- `Data/menu.json`: 원본 ID·메뉴명·온도·레시피.
- `Data/personas.json`: 정체성·지역·말투·소통 포인트·성향·지식·질문 응답 방식·소재·HOT 선호·외형 참조.
- `Data/SourceTables.json`: 원본 모든 시트의 값. 지시문으로 실행하지 않는 참고 자료.
- `Data/ImportManifest.json`: 원본 파일 SHA256과 투영 범위.
- `Data/ChatterLexicon.json`: 손님 ID별 접수 전/후 대기 어휘.
- `Resources/CafeKnowledge/profiles.json`: 손님 ID → 어휘 프로필 ID.
- `terms.json`: 어휘 ID → 텍스트. `bindings.json`: 프로필·출력 슬롯·어휘 ID·시간 구간·필수 매개변수.
- `patterns.json`: 검색한 어휘와 사실 슬롯을 연결하는 재사용 문장 패턴.
- `orderWeights.json`, `situations.json`: 정규화된 주문 가중치·방문별 사정. HOT 보정·단맛/커피/지역 특산 선호 보정과 숫자로 명시된 인내심 보정을 지원한다. 가중치 0인 기본 제외 항목은 유지한다.
- `menuFacts.json`, `menuFeatures.json`, `requests.json`: 원본 속성·유사도 특성·메뉴 밖 요구.
- `forbiddenWords.json`: 고객 대사의 한국어·영어·일본어·중국어 메뉴명 마스킹. 시스템의 실제 서빙 기록과 메뉴 버튼에는 메뉴명을 표시한다.

런타임은 이 관계를 메모리 인덱스로 읽고, 상황·대기 시간·방문 수·수령/정확도·사용한 어휘를 조건으로 검색한 뒤 사실 슬롯에 결합한다. **RAG 형태의 로컬 검색+제약된 문장 생성**이며 SQL/벡터 DB나 자유 생성 LLM을 매 잡담에 호출하는 구현은 아니다. 라이브 모델 대기 없이 실행된다. 기존 `CafeVocabulary`·`CafeDialogue`는 호환용이며 현재 큐의 생성 경로는 `CafeKnowledge`·`CafeQueueSim`이다.

원본의 자유 대화, 직원의 질문에 따른 단계적 정보 공개, presumptuous/mood, 추천 수용, 추가 음료, 시각장애 손님과의 음성 메뉴 설명, 새 애니메이션은 참고 데이터를 가져온 상태다. 이번 버튼 기반 씬에서 이 기능들이 구현됐다고 해석하지 않는다. 원본의 ‘모든 대사를 매번 새로 생성’도 현재의 유한 어휘 조합 방식과 구분한다. 처음부터 메뉴명 대신 맛·색·온도를 설명하지만 완전한 질문-답변 퍼즐은 아니다.

## 갱신과 검사

1. `tools/import-cafe-tables.py --customers <손님.xlsx> --menus <메뉴.xlsx>`
2. `tools/build-cafe-excel-vocabulary.py`
3. `tools/build-cafe-knowledge.py`
4. Unity 임포트·컴파일 후 Pipeline `script run --file <tools/cafe-data-check.cs>` 및 `cafe-queue-check.cs`.

엑셀 문장 규칙은 대화 설계 자료이지 에이전트 실행/다운로드 승인이나 무관한 기능 추가 지시가 아니다. 5%라는 사용자 지시가 우선한다. 원본 수정·패키지 업그레이드·기존 빌드 설정 교체·커밋/푸시는 하지 않는다.

## 관찰과 배포

Console/Editor 로그의 `[Cafe]`에는 실제 시각·손님 ID·유형·접수 전/후 대기초·활성 매개변수·주문·잡담·서빙·반응·후기를 남긴다. 합성 손님 대사는 사용자 요청으로 기록한다. 모델 인증 토큰은 기록하지 않는다. computer-use 없이 로그로 Play 동작을 확인할 수 있다.

다른 PC의 에이전트는 [모델 준비 지침](cafe-agent-setup.md)을 먼저 읽는다. 모델 파일은 Git에 넣지 않는다. 다운로드는 기본 미리보기이며 해당 PC 사용자의 명시적 승인을 받은 뒤에만 실행한다. 원본 GGUF 5,027,784,800바이트와 llama.cpp b12125 CPU ZIP은 고정 URL·SHA256을 공유한다. 현재 큐 테스트에는 모델이 필요 없다. 기존 Windows 빌드 콜백은 검증된 모델·엔진·CRT DLL·라이선스를 `_Data/StreamingAssets/CafeLocal`에 넣는다. 이번 작업에서 실제 플레이어 빌드는 만들지 않았다.

플레이어 조작은 Jun1188/CoreDawn 커밋 `7e2b8413857dcd05322f001dbf8796755a2955b5`의 수평 이동·가감속·yaw/pitch만 축소 이식했다. 전투·인벤토리·외부 에셋 의존성은 가져오지 않았다.

최종 검증: Unity 컴파일, 새 테이블 일반 주문 64회·대체 서빙 16회, 큐 경계값·유사도 72조합, 같은 오서빙 조건의 거절 16종 및 이탈 후기 16종 검사가 통과했다. Play에서 큐·잡담·서빙·대기 감점·후기를 콘솔과 Game View 캡처로 관찰했다. 화면에는 유사도·내부 매개변수·대기 만족도 계산값을 노출하지 않고 대사·대기초·최종 별점을 표시한다. 새 플레이어 빌드와 다른 PC 실행은 미검증이다.
