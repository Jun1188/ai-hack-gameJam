# HUD·입력·보행·Hierarchy·카메라 원인 점검

2026-11-05. 에이전트가 빌드나 Play Mode를 시작하지 않고 코드, 저장된 에셋, 열린 Editor, 원본 애니메이션을 조사했습니다. 마지막 확인 시 사용자가 실행한 Play Mode가 감지되어 중단·씬 재생성 없이 현재 상태만 읽었습니다.

## 확인된 사실과 수정

| 문제 | 확인된 구현/검증 문제 | 수정 |
|---|---|---|
| HUD 잘림 | IMGUI 절대 좌표·직접 GUI 행렬·월드 라벨 투영을 혼합했습니다. 초기 라벨은 화면 밖을 검사하지 않았고, 단순 Rect 계산 검사를 실제 Game 뷰 레이아웃 검증처럼 보고했습니다. 첫 보정 후에도 사용자의 잘림이 재현됐으므로 단일 좌표 원인만으로 해결됐다고 볼 수 없습니다. | UI Toolkit의 flex/wrap 레이아웃·UIDocument·PanelSettings로 교체하고 영역별 overflow를 제한했습니다. 좁은 창에서 메시지/버튼을 줄바꿈합니다. |
| 한글 입력 불가 | IMGUI 입력에 Keyboard IME 활성화·조합 처리 연결이 없었습니다. 입력창으로 포커스를 강제로 되돌리는 코드가 있었고 Enter 전송이 조합 확정과 충돌할 수 있었습니다. | 표준 TextField, 포커스별 SetIMEEnabled, 조합 중 전송 방지, 커서 위치 연결. Enter는 조합 확정/줄바꿈, Ctrl+Enter 또는 버튼은 전송입니다. |
| 부자연스러운 걷기 | 이동 속도 2.4가 고정되어 클립 보폭과 독립적이었고, 방향을 즉시 LookRotation으로 바꿨습니다. 충돌 때 moving이 매 프레임 바뀌면 Idle/Walk 트리거가 왕복할 수 있습니다. | 기본 속도 1.35, 가감속·초당 최대 회전각, 0.12초 정지 유예, 실제 이동 속도 기반 WalkRate를 사용합니다. 1.35는 조정 가능한 기준값이며 원본 보폭에서 정밀 추정한 값은 아닙니다. |
| Hierarchy에 스테이지가 없음 | 씬 생성기는 Camera/Light/Systems만 저장하고 스테이지를 Start에서 생성했습니다. 편집 가시성 자체가 빠져 있었습니다. | 편집용 미리보기를 동일 JSON으로 저장합니다. Environment/Parts/Nodes/Memory/Characters 그룹을 만들고 Play 시작 때 미리보기만 교체합니다. |
| R 회전/흔들림 | R 한 번에 90도 목표를 추가하는 구현이었습니다. 회전각마다 최대 줌도 바뀌어 화면 배율이 흔들릴 수 있었습니다. | R 유지 시 일정 각속도로 연속 회전, Shift로 역회전. 한 바퀴 전체에서 안전한 줌 한계를 해석적으로 계산해 회전 중 크기를 고정합니다. |

## 걷기 파일이 잘렸는가

제공된 `Downloads/grand_9walk.fbx`와 프로젝트 `Animations/Walk.fbx`의 SHA256은 모두 `2717A232B8180D6999231A4BF138A5FC04AD61D47B31AC4DE58EE90893584ED8`입니다.

열린 Editor의 ModelImporter에서 원본 default take와 실제 clipAnimations를 대조했습니다. 둘 다 `Armature.001|mixamo.com`, **0~111프레임**이며 실제 clip과 preview clip 모두 **24fps, 4.625초**입니다. 현재 임포트가 중간을 잘랐다는 증거는 없습니다.

그러나 원본을 무변환 재생한 것은 아닙니다. Humanoid 리타게팅, 루프/루프 포즈, 루트 XZ 고정(제자리 걷기), 코드 위치 이동을 사용합니다. 이 처리와 이동 속도/전환 타이밍이 체감 보행을 바꿉니다. 원본 클립 자체의 전후 동작과 루프 연결 품질은 사용자 Play 검증이 필요합니다. 지팡이 전용 보행/손 IK도 없습니다.

## CoreDawn과 명세 문제

프로젝트 Scripts에서 CoreDawn 코드/네임스페이스 참조는 발견되지 않았습니다. 가져온 것은 Sim/Game/Presentation/Data라는 책임 분리 원칙입니다. 외부 CoreDawn 런타임이 이번 문제를 일으켰다는 증거는 없습니다.

반면 구현 결정을 정당화할 수 있는 명세와 검증이 부족했습니다. Game 뷰의 DPI/레이아웃, IME 조합, 편집 상태의 스테이지 가시성, 이동 단위와 클립 속도의 관계를 통합 요구사항으로 다루지 않았습니다. 처음의 90도 회전 선택도 현재 요구하는 연속 회전과 맞지 않았습니다. 이러한 부분을 구현 기본 동작으로 보완했습니다.

이전에는 Animator 상태 이름이나 수학적 Rect가 맞으면 실제 동작도 맞는 것처럼 보고했습니다. 상태 전환 성공은 자연스러운 보행을 보장하지 않고, 문자열 왕복은 Windows IME 입력 검증을 대신하지 않습니다. 앞으로 결과를 구분해 기록해야 합니다.

## 배율과 원본 메시의 별도 관찰

현재 Game 뷰는 pixelsPerPoint/backingScale/minScale/zoomAreaScale이 모두 1.5입니다. 1.5 표기는 이 환경의 최소 맞춤 배율이므로 잘림을 임의 확대 탓으로 돌리지 않았습니다.

모델 재임포트 시 자기 교차 폴리곤 1개가 버려진다는 Unity 경고가 있습니다. 원본 메시 품질 문제로 별도 기록하며, 걷기 구간 누락이나 한글 입력 실패의 원인이라는 증거는 없습니다.

## 검증 범위

- 열린 Editor에서 컴파일·UXML/USS 임포트, 필수 UI 컨트롤·한글 문자열 왕복, 미리보기 저장, 기존 규칙 검사를 수행합니다.
- 수동 PlayableGraph에서 Idle/Walk 전환과 메시 변형을 검사하며 Editor Play Mode에는 들어가지 않습니다.
- 카메라가 회전 중 줌을 바꾸지 않고 맵 안을 유지하는지 각도·화면 비율별 검사합니다.
- 실제 Windows 한글 조합/후보 선택, 다양한 Game 뷰 크기의 HUD 표시, 보행 체감, R 입력은 사용자 Play 검증 대상입니다. 이를 완료했다고 보고하지 않습니다.

마지막 읽기 전용 확인 결과:

- 컴파일 실패 없음, 콘솔 오류 0개. 실행 중 카메라의 `orbitDegreesPerSecond=60`, 연속 방위각과 `WellHud` UIDocument 패널 연결을 확인했습니다.
- 현재 패널 1183.24×665.07에서 phase/message/request/stop의 실제 레이아웃 경계는 패널 내부였습니다. 숨겨진 채팅창이나 다른 해상도까지 검증한 것은 아닙니다.
- Animator 아바타 유효, Walk/Idle/WalkRate 파라미터와 Idle 8.333초·Walk 4.625초 클립 연결을 확인했습니다.
- 게임 객체를 변경하지 않는 투영 계산으로 3개 화면 비율 × 72개 방위각 × 4개 화면 모서리, 총 864개 지상 교차점을 검사했습니다. 모두 30×26 맵 안이며 최소 여백은 약 0.300입니다. 회전각과 무관한 고정 줌 상한을 사용합니다.
- 패키지 manifest/lock 변경은 없습니다.

편집용 배치는 JSON의 미리보기입니다. 미리보기 객체를 직접 옮긴 것은 데이터에 저장되지 않으므로 지속적인 배치 변경은 JSON에서 해야 합니다.
